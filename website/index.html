CORE TECHNOLOGY

Designed around verifiable state and cryptographic agility.

Axven’s architecture is built to evolve without sacrificing deterministic chain behavior.

⛏

Proof of Work

Cumulative-chainwork fork selection with deterministic replay and reorganization behavior.

◫

UTXO + Sparse Merkle Tree

UTXO state commitments backed by Sparse Merkle Tree infrastructure and deterministic roots.

⌁

Post-Quantum Cryptography

Ed25519 (N), ML-DSA-44 (M), and hybrid Ed25519 + ML-DSA authorization (H).

⇄

Witness-Separated Transactions

Transaction identity remains separated from witness material, supporting stable transaction semantics.

◉

Peer-to-Peer Networking

TCP-based node communication with synchronization, propagation, reconnect behavior, and bounded resources.

▣

Wallet + RPC + CLI

Persistent encrypted wallet storage, local JSON-RPC, CLI workflows, and operator-focused tooling.

ROADMAP

From reference core to production-grade network.

The current focus is correctness, hardening, and measurable performance — before premature optimization.

FOUNDATION

Consensus, UTXO state and devnet identity

Deterministic genesis, chainwork fork choice, state commitments, replay and reorg invariants.

CURRENT

Security hardening and reference-core stabilization

Bounded P2P/RPC surfaces, wallet safety, node lifecycle reliability, validation coverage and release discipline.

NEXT

Performance profiling + native acceleration

Measure real bottlenecks, then move selected hot paths into an axven_native Rust layer while keeping Python as the reference implementation.

LATER

Multi-node testnet and production readiness

Long-running multi-node tests, packaging, bootstrap infrastructure, operator docs, public testnet observation, and only then a mainnet decision.

SECURITY MODEL

Correctness first. Limits everywhere.

Axven’s security work treats malformed inputs, resource exhaustion, state races, and restart/reorg behavior as first-class protocol engineering problems.

  • Bounded RPC request size and concurrency
  • Bounded P2P peers, messages, sync batches and orphan pools
  • Atomic chain-state reads across reorgs
  • Deterministic validation and release manifests
  • Regression contracts for security invariants
Reference coreHARDENING

Axven does not claim to be production-ready or externally audited. Security work is ongoing and public testing will precede any mainnet decision.
